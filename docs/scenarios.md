# Demo 情境與驗收條件

每個模組都為下列情境服務。情境通過 = 里程碑完成。

## 假資料

| 系統 | 資料 |
|---|---|
| 工單 | **T-1001**（王小明／O-2001，指派 alice，外套未到想改寄公司）、T-1002（陳美玲，指派 bob）、T-1003（林大偉，指派 alice，想取消訂單） |
| 訂單 | **O-2001** 藍色羽絨外套 2,980 元，已出貨 → S-3001；O-2002 已送達；O-2003 已出貨 → S-3003；O-2004 未出貨 |
| 物流 | **S-3001** 桃園轉運中心延誤（可改寄，手續費 60 元）；S-3002 已送達；S-3003 配送中（不可改寄） |
| 補償規則 | cs_agent 單筆上限 100 元，cs_supervisor 500 元 |

> 用語：Copilot 上的人工動作一律稱「**確認**」（確認意圖）；「核准／簽核」只用於舊系統內的業務流程。見 [ADR-0003](adr/0003-confirmation-vs-authorization.md)。

## 情境 1：跨系統查詢 + 提單 + 舊系統人員執行（主 demo）

**alice**：「T-1001 的客人外套還沒到，可以改寄公司嗎？運費能不能補償？」

Agent 預期行為：
1. 工單系統：讀 T-1001 → 取得客戶、訂單、新地址
2. 訂單系統：讀 O-2001 → 取得貨件 S-3001
3. 物流系統：讀 S-3001 → 狀態 DELAYED，可改寄，手續費 60 元
4. 回覆：「貨件在桃園轉運中心延誤，目前可以改寄，手續費 60 元，建議以運費補償 60 元（在你的權限內）」
5. 查規章（強制節點），產生**附引用出處的行動卡片**，alice 確認意圖後**依序**提單（ADR-0006）：
   - 先：改寄 S-3001 至「台北市信義區松仁路 100 號 12 樓」→ 在物流系統建立**改寄申請（待執行）**
   - 後：改寄執行完成後，才提交補償 T-1001 運費 60 元（在 alice 上限內，工單系統直接生效）
6. **切到舊系統的 Vue 畫面**：物流系統原本的審核清單出現新申請單，標示「來源：AI Copilot／申請人：alice」
7. 物流人員照平常流程審核並執行 → 地址才真正變更
8. Copilot 上的卡片狀態從「已提單、待執行」更新為「已完成」，並寫一筆工單備註

驗收：
- [ ] 查詢步驟全部自動執行，且在 UI 上可展開看到呼叫參數與結果
- [ ] alice 確認前**沒有**任何申請單產生
- [ ] alice 確認後、物流人員執行前，貨件地址**仍未變更**
- [ ] alice 可以在卡片上修改地址後再送出
- [ ] 舊系統頁面顯示申請單與「來源：AI Copilot」標記
- [ ] 稽核 log 記錄：使用者、tool、參數、確認時間、舊系統回應

## 情境 2：越權被擋

**alice**：「幫我看一下 T-1002 的客人要什麼」

- [ ] 工單系統回 403，Agent 回覆「這張工單沒有指派給你」，不嘗試其他方式取得
- [ ] 稽核 log 記錄被拒的呼叫

## 情境 3：超出權限 → 進入舊系統既有的主管簽核流程

**alice**：「客人很生氣，直接補償 200 元折價券」

- [ ] 卡片預檢提示「超過你的上限 100 元，將送主管簽核」
- [ ] alice 確認後，工單系統建立**待主管簽核**的補償申請（不是直接失敗，也不是 AI 自行放行）
- [ ] carol 在**工單系統自己的待簽核頁面**看到申請單（來源：AI Copilot），核准後補償才生效

## 情境 4：部分完成（ADR-0006）

物流人員退回 S-3001 的改寄申請

- [ ] 補償申請**不會**被送出
- [ ] Copilot 卡片顯示「改寄被退回（原因：……）」，並提供後續選項給 alice
- [ ] 申請單超過 SLA 未處理時，Copilot 提醒 alice

## 情境 5：不可改寄（邊界條件）

**carol**：「T-1002 的客人也想改地址」

- [ ] 物流系統顯示 S-3003 已在配送中 → Agent 說明無法改寄，建議聯繫物流商或拒收後重寄
