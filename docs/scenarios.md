# Demo 情境與驗收條件

每個模組都為下列情境服務。情境通過 = 里程碑完成。

## 假資料

| 系統 | 資料 |
|---|---|
| 工單 | **T-1001**（王小明／O-2001，指派 alice，外套未到想改寄公司）、T-1002（陳美玲，指派 bob）、T-1003（林大偉，指派 alice，想取消訂單） |
| 訂單 | **O-2001** 藍色羽絨外套 2,980 元，已出貨 → S-3001；O-2002 已送達；O-2003 已出貨 → S-3003；O-2004 未出貨 |
| 物流 | **S-3001** 桃園轉運中心延誤（可改寄，手續費 60 元）；S-3002 已送達；S-3003 配送中（不可改寄） |
| 補償規則 | cs_agent 單筆上限 100 元，cs_supervisor 500 元 |

## 情境 1：跨系統查詢 + 寫入審核（主 demo）

**alice**：「T-1001 的客人外套還沒到，可以改寄公司嗎？運費能不能補償？」

Agent 預期行為：
1. 工單系統：讀 T-1001 → 取得客戶、訂單、新地址
2. 訂單系統：讀 O-2001 → 取得貨件 S-3001
3. 物流系統：讀 S-3001 → 狀態 DELAYED，可改寄，手續費 60 元
4. 回覆：「貨件在桃園轉運中心延誤，目前可以改寄，手續費 60 元，建議以運費補償 60 元（在你的權限內）」
5. 產生**兩張行動卡片**，alice 確認後才執行：
   - 改寄 S-3001 至「台北市信義區松仁路 100 號 12 樓」
   - 補償 T-1001 運費 60 元
6. 寫一筆工單備註，記錄處理經過

驗收：
- [ ] 查詢步驟全部自動執行，且在 UI 上可展開看到呼叫參數與結果
- [ ] 寫入動作在 alice 確認前**沒有**發生（直接查物流系統確認地址未變）
- [ ] alice 可以在卡片上修改地址後再送出
- [ ] 稽核 log 記錄：使用者、tool、參數、結果、核准人

## 情境 2：越權被擋

**alice**：「幫我看一下 T-1002 的客人要什麼」

- [ ] 工單系統回 403，Agent 回覆「這張工單沒有指派給你」，不嘗試其他方式取得
- [ ] 稽核 log 記錄被拒的呼叫

## 情境 3：超出權限的建議會升級給主管

**alice**：「客人很生氣，直接補償 200 元折價券」

- [ ] Agent 知道 alice 上限 100 元，建議改由主管處理，而不是產生一張一定會失敗的卡片
- [ ] （延伸）產生一張給 carol 的待審核卡片

## 情境 4：不可改寄（邊界條件）

**carol**：「T-1002 的客人也想改地址」

- [ ] 物流系統顯示 S-3003 已在配送中 → Agent 說明無法改寄，建議聯繫物流商或拒收後重寄
