# ADR-0004：LLM 可切換（demo 雲端、正式地端），以 RAG 讓行為對齊既有規章

- 狀態：已採納
- 日期：2026-09-28

## 背景

- **開發與 demo 使用雲端 LLM API**；**正式環境一律地端部署**，內部資料不得外送
- 刻意**不以低階地端模型（例如筆電 GPU 可跑的小型量化模型）為開發目標**：
  本專案要驗證的是架構，不是補足小模型能力；正式上線所需的地端 GPU 與模型等級，由導入單位依評測結果準備
- Agent 的建議必須盡量符合公司既有的規章與 SOP（補償辦法、客服作業規範、個資告知等）
- 但 RAG 屬於機率性機制（檢索可能漏、模型可能誤讀或被 prompt injection 誘導），不能單獨作為合規保證

## 決策

### 1. 模型存取統一走 OpenAI-compatible API

- Agent 端只依賴一組設定：`LLM_BASE_URL`、`LLM_MODEL`、`LLM_API_KEY`
- 以 LangChain `init_chat_model` 讀取設定；程式中**不得直接使用任何廠商專屬 SDK**
- 地端推論使用 vLLM（正式、K8s GPU 節點）或 Ollama（開發機），兩者皆提供 OpenAI 相容 endpoint
- 切換雲端／地端 = **只改環境變數，不改程式**

### 2. Embedding 從 demo 起即採地端模型

- 規章文件屬內部資料，embedding 同樣不得外送
- 更換 embedding 模型需整批重建索引，因此**一開始就固定使用地端多語 embedding 模型**（候選：bge-m3 類）
- Embedding 設定同樣抽成環境變數，並在索引 metadata 記錄模型名稱與版本，模型不一致時拒絕查詢

### 3. 保持可移植性，並以評測集作為上線驗收標準

- **不使用雲端獨有功能**：廠商專屬的 prompt caching、伺服器端內建 tool、超長 context 等，地端不一定具備，一律不依賴
- **評測集 = 上線驗收標準**：地端模型必須通過同一組評測（見 [scenarios.md](../scenarios.md)）才能上線；
  需要多強的 GPU／模型，由評測結果決定，而非事先承諾
- 下列設計同時提升雲端與地端模型的穩定度：

- 單次提供給模型的 tool 數量盡量少，依使用者角色與當下頁面篩選
- Tool 參數盡量使用 enum 與結構化輸出，降低填錯機率
- 關鍵流程順序由 **LangGraph 固定節點**控制，不完全交由模型決定
- 模型可依 LangGraph 節點分別設定（簡單分類用小模型、規劃用大模型），為日後地端成本最佳化預留空間

### 4. RAG 設計：讓 Agent 的建議對齊既有規章

| 項目 | 做法 |
|---|---|
| 切塊 | **一條規定一個 chunk**；metadata 含辦法名稱、條號、生效日期、適用角色／情境 |
| 檢索 | **Hybrid retrieval**（pgvector 向量 + 全文關鍵字），規章用語與條號需精確比對 |
| 強制查詢 | 產生**寫入類建議**前，graph 必經「查規章」節點，模型不能跳過 |
| 引用驗證 | 卡片引用的條文必須出現在本次檢索結果中（程式比對 chunk id），否則視為編造，不產生卡片 |
| 無依據 | 查無相關規定時不給建議，改為提示「查無相關規定，請洽主管」 |
| 版本控管 | 只檢索目前生效版本；舊版保留，供稽核時還原當時依據 |

卡片上顯示引用出處（例如「依《物流延誤補償辦法》第 3 條」），讓使用者與稽核人員可以查證。

### 5. 分工原則：RAG 負責「依據」，確定性規則負責「執行」

- 會決定**能不能做**的規則 → 舊系統（權限、狀態、上限、簽核）與 Adapter（風險分級、欄位裁切、頻率限制），見 ADR-0002、ADR-0003
- 說明**建議怎麼做、為什麼**的知識 → RAG
- 規則不複製：同一條規定若同時存在於規章文件與舊系統程式中，**以舊系統程式為準**

## 合規分層總覽

1. 輸入把關：prompt injection 偵測、主題範圍限制、個資識別
2. RAG：提供規章依據與引用出處
3. Agent 推理，提出建議
4. 確定性執行規則：Adapter + 舊系統
5. 人工確認（ADR-0003）+ 舊系統既有簽核
6. 輸出把關與稽核：回覆中的個資遮罩、每一步寫入稽核紀錄

## 取捨

- 開發期以雲端模型驗證，地端表現在導入前未知；以評測集把風險顯性化，交由導入單位決定硬體等級
- 地端部署需要 GPU 資源與模型維運（版本更新、效能監控），屬導入單位責任
- 強制查詢與引用驗證會增加延遲，且在規章不完整時會較常回覆「查無依據」——這是刻意選擇保守

## 附帶價值

「雲端 vs 地端模型」×「有無 RAG」×「有無強制查詢節點」可直接作為 ablation 實驗設計。
