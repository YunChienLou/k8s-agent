# ADR-0001：以外掛 adapter pod 導入 AI，而非修改舊系統

- 狀態：已採納
- 日期：2026-09-28

## 背景

要讓 AI Agent 使用既有企業系統，有兩種主要做法：

1. 在舊系統內加 SDK／annotation，直接開出 tool（例如 Spring AI `@Tool`）
2. 在舊系統外部加一個 adapter，透過既有 REST API 轉譯成 tool

## 決策

採用做法 2：**同一個 adapter image，每個舊系統配一份 `tools.yaml` 部署一次**。

## 理由

- 傳統企業導入 AI 最大的阻力是「要動核心系統」：需要排版本、回歸測試、甚至原開發團隊已不存在
- 舊系統 API 是給程式用的（細碎、要 ID、回傳肥大），直接 1:1 暴露給 LLM 效果差；
  adapter 可以在不改舊系統的前提下，組合成**任務型 tool** 並裁切欄位
- 新增一個系統 = 新增一份設定檔，不需要重新 build

## 取捨

- 語意受限於既有 API：舊系統沒有的能力，adapter 也做不出來
- 多一跳網路延遲
- 若舊系統仍有團隊積極維護，做法 1（starter）語意最精準，列為 roadmap 選配

## 備註

「OpenAPI → MCP 轉換」本身已被開源工具與 API Gateway 產品商品化；
本專案的差異化在於任務型 tool 組合、風險分級、審核與稽核。
